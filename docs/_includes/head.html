{% comment %} Full override of minima's _includes/head.html. minima ships a `custom-head.html` extension point, but only from some release onward — the version GitHub Pages actually builds with (2.5.1, per https://pages.github.com/versions/) predates it and never calls it (see https://github.com/jekyll/minima/issues/472). A site-level _includes file always wins over the theme gem's own copy of the same path, so overriding head.html directly is the version-proof way to add JSON-LD here, instead of depending on an include hook that may or may not exist in whatever minima version Pages happens to be running. Everything up to the closing mirrors minima 2.5.1's head.html (meta tags, seo tag, stylesheet, feed_meta, conditional Google Analytics) so nothing else regresses; the JSON-LD block is the only addition. Keep this a Liquid comment block, and never write Liquid tag syntax inside it — not even as an example. Two separate outages came from ignoring that: 1. As an HTML comment, the seo tag named below still rendered (Liquid evaluates tags anywhere, comments included). It emits its own HTML end-comment marker, whose "--" + ">" closed this comment early and leaked the remaining prose plus a duplicate head element into the page. 2. Rewritten as a Liquid comment, spelling out the opening comment tag in prose opened a *nested* comment block, so the closing tag below matched the inner one and the outer block was never closed. That's a hard build failure: "Liquid syntax error: 'comment' tag was never closed". Refer to tags by name only (seo tag, feed_meta, endcomment), never in brace-percent form. {% endcomment %} {%- seo -%} {%- feed_meta -%} {%- if jekyll.environment == 'production' and site.google_analytics -%} {%- include google-analytics.html -%} {%- endif -%} {%- if page.url == "/" -%} {%- elsif page.url contains "/processors/" or page.url == "/benchmarks/" or page.url == "/comparison/" -%} {%- endif -%}
